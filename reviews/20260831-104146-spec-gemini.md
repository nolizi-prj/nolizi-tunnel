## 1. Coherence & Internal Consistency

- **Single Source of Truth ([L-007](file:///home/m/dev/governance/lessons/L-007-restating-a-rule-forks-it.md)):** [`SPEC.md`](file:///home/m/dev/pumasi-tunnel/spec/0001-public-scheme/SPEC.md) §1 establishes that `core.Registry.publicScheme` applied by `Registry.PublicURL` is the sole source of truth for scheme prefixing across all three user surfaces (CLI output via `AuthResponse.URL`, Apex Console status JSON via `/_pumasi/status`, and Zero-install SSH greeting via `sshGreet`). No surface constructs or assumes its own URL scheme independently.
- **Configuration & Validation Flow:** The configuration pipeline defined in [`SPEC.md`](file:///home/m/dev/pumasi-tunnel/spec/0001-public-scheme/SPEC.md) §2–§3 flows strictly through `flag` → `relay.Config.PublicScheme` → `relay.New` (validated via `core.ParsePublicScheme`) → `core.NewRegistry` → `Registry.publicScheme`.
- **Failure Modes & Defaults:**
  - `core.ParsePublicScheme` normalizes inputs (`http`, `https`, case insensitivity, surrounding whitespace, and trailing `://`) and defaults empty input to `http`.
  - `relay.New` returns `core.ErrUnknownScheme` and fails fast on any invalid scheme at startup.
  - `core.NewRegistry` fails closed to `http` if given unvalidated input, ensuring downstream registry consumers never emit unroutable schemes.
- The URL construction formula in §4 ($PublicURL(N) = S + \text{"://"} + lower(N) + \text{"."} + D$) is mathematically consistent with domain normalization and subdomain validation rules.

## 2. Intent Statement Alignment ([L-005](file:///home/m/dev/governance/lessons/L-005-review-checks-coherence-not-intent.md))

- [`INTENT.md`](file:///home/m/dev/pumasi-tunnel/spec/0001-public-scheme/INTENT.md) identifies the live defect: `Registry.PublicURL` hardcoded `"https://"` while the relay did not terminate TLS, producing non-functioning URLs across all surfaces by default.
- [`SPEC.md`](file:///home/m/dev/pumasi-tunnel/spec/0001-public-scheme/SPEC.md) precisely targets this gap by introducing a truthful default (`http`), allowing operator configuration of `https` when an external TLS terminator is deployed, and refusing invalid schemes at startup.
- Non-goals (in-relay TLS termination, wildcard certificate provisioning, announce-before-bind race condition handling, and `README.md` rewrites) are strictly preserved across both [`INTENT.md`](file:///home/m/dev/pumasi-tunnel/spec/0001-public-scheme/INTENT.md) and [`SPEC.md`](file:///home/m/dev/pumasi-tunnel/spec/0001-public-scheme/SPEC.md) §6. The spec does not over-scope or diverge from the declared intent.

## 3. Acceptance Cases & Verification Invariants ([L-006](file:///home/m/dev/governance/lessons/L-006-tests-that-cannot-fail.md))

Each acceptance case defined in [`acceptance/CASES.md`](file:///home/m/dev/pumasi-tunnel/spec/0001-public-scheme/acceptance/CASES.md) (A-1 through A-10) specifies a concrete, deterministic execution under which it will fail:

1. **A-1 & A-2 (Registry Scheme Invariants):** Unconditionally assert that `PublicURL` emits `http` by default and `https` when explicitly configured. Fails if either scheme is ignored or hardcoded.
2. **A-3 & A-4 (Scheme Normalization & Failsafe):** Test `ParsePublicScheme` across valid spellings and invalid schemes (`ftp`, `htp`, `ws`, `HTTPs://x`, `http s`), and assert that `NewRegistry` fails closed to `http`.
3. **A-5, A-6, A-7 & A-8 (Surface Parity & Multi-Surface Invariance):** Unconditionally assert that Surface 1 (CLI `AuthResponse`), Surface 2 (Apex Console `/_pumasi/status`), and Surface 3 (SSH greeting channel) each reflect the configured scheme, and assert mutual agreement across all three surfaces of a single relay under both schemes.
4. **A-9 (Startup Validation):** Asserts that `relay.New` returns `core.ErrUnknownScheme` and halts on invalid schemes rather than silently coercing.
5. **A-10 (Isolation of Scheme Configuration):** Asserts that changing the scheme affects only the scheme prefix, leaving host normalization, subdomain lowercasing, base domain handling, and `TCPAddr` completely untouched.

None of the acceptance cases contain conditional assertions on non-deterministic races or vacuous pass conditions.
