## 1. Coherence & Internal Consistency

- **Architectural De-coupling ([SPEC.md §2–§3](file:///home/m/dev/pumasi-tunnel/spec/0002-bind-before-announce/SPEC.md#L17-L47)):**  
  The root cause of the existing announce-before-bind ordering is the coupling in `bindTCP` between socket creation (`net.Listen`) and the accept/forwarding loop (`serveTCP`), which requires an active `mux.Server` session. Because initializing `mux.Server(conn)` immediately spawns a background `readLoop` goroutine on the raw connection, doing so before transmitting the handshake response would corrupt handshake frame processing. Splitting `bindTCP` into:
  1. `listenTCP(agentID string, port int) (*tcpListener, error)` — binds the OS listener and registers it in `r.tcpListeners`, buffering incoming visitor connections in the kernel backlog;
  2. `serveTCP(session tunnelSession, l *tcpListener, subdomain string)` — drains accepted connections into multiplexed streams once the session handshake completes;  
  cleanly breaks the circular dependency without race conditions or protocol corruption.
- **Elimination of Registry Round-Trip ([SPEC.md §3.2](file:///home/m/dev/pumasi-tunnel/spec/0002-bind-before-announce/SPEC.md#L53-L70)):**  
  Updating `authorize` to return `(core.AuthResponse, int, error)` delivers the allocated TCP port directly to `ServeAgent` and `ServeSSH`. This eliminates the secondary lookup `r.registry.Lookup(resp.Subdomain + "." + r.cfg.BaseDomain)` from both paths. As documented in [`lessons/L-007`](file:///home/m/dev/pumasi/lessons/L-007-restating-a-rule-forks-it.md), deleting the redundant lookup eliminates the mechanism of the silent skip entirely rather than patching it with conditional branches.
- **Lifecycle & Teardown Symmetry ([SPEC.md §3.3](file:///home/m/dev/pumasi-tunnel/spec/0002-bind-before-announce/SPEC.md#L71-L83)):**  
  If encoding or writing `AuthResponse` fails after `listenTCP` succeeds, the spec explicitly requires closing the listener, releasing the port via `releaseTCP`, and unregistering the agent. The listener cannot outlive a failed handshake.

## 2. Intent Statement Alignment ([L-005](file:///home/m/dev/pumasi/lessons/L-005-review-checks-coherence-not-intent.md))

- [`INTENT.md`](file:///home/m/dev/pumasi-tunnel/spec/0002-bind-before-announce/INTENT.md) identifies two concrete failure modes:
  1. The agent path announces `TCPAddr` in `AuthResponse` before `bindTCP`, leading to intermittent connection refused errors for clients dialling the newly announced port.
  2. The SSH path contains a silent failure on lookup error (`lookupErr != nil`), leading to dead announced addresses on configurations like `BaseDomain: ""` (`-domain ""`).
- [`SPEC.md`](file:///home/m/dev/pumasi-tunnel/spec/0002-bind-before-announce/SPEC.md) precisely addresses both paths by establishing the rule: *"A public address leaves this relay only after the listener that answers it is bound. If it cannot be bound, the caller is told the failure instead of an address, never after one."*

  - **B-6 (End-to-End Regression Invariant):** Unconditionally asserts bidirectional data flow on the happy path across the split `listenTCP`/`serveTCP` lifecycle.

## 4. Edge Cases & Boundary Handling

1. **HTTP-Only Requests (`resp.TCPAddr == ""`):** Handled cleanly without invoking `listenTCP` or `serveTCP`.
2. **OS Bind Failures vs. Pool Allocation Failures:** Pool exhaustion is rejected during `authorize`; external OS socket collisions (e.g. `EADDRINUSE`) are caught during `listenTCP`, releasing the allocated port back to `r.pool` before returning.
3. **Visitor Arrival During Handshake Window:** In-flight TCP connections arriving between `listenTCP` and `serveTCP` complete the kernel TCP handshake and queue safely in the OS listen backlog until `serveTCP` begins accepting.
4. **Early Client Disconnects:** Handled symmetrically via `defer releaseTCP` / `defer session.Close()` and `<-session.CloseChan()`.
