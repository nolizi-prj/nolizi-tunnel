## 1. Intent Statement Alignment ([`lessons/L-005`](file:///home/m/dev/pumasi/lessons/L-005-review-checks-coherence-not-intent.md))

[`INTENT.md`](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/INTENT.md) precisely identifies the architectural gap in the tree:
1. `Tunnel.Reserved` is set based purely on request syntax (`req.Subdomain != "" && req.Token != ""`) and never enforced or inspected.
2. `core.Registry` and `core.PortPool` are purely in-memory maps that drop registrations and ports on disconnect, creating an unprotected window where anonymous agents can seize a name or port during reconnect backoff (Window a) or after a relay restart (Window b).
3. The intent establishes the core invariant: *a name and its associated public TCP port belong to whoever first proved they held them and persist across disconnects, while live TCP connections remain bounded by nature.*

[`SPEC.md`](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md) cleanly implements this intent:
- **Explicit Slicing (§4, §7):** Slice 1 builds in-memory reservation and port holding to close the reconnect window (Window a); Slice 2 specifies persistent storage to close the relay restart window (Window b); Slice 3 defers SSH token grammar and operator seeding.
- **Strict Non-Goals (§8):** Explicitly avoids out-of-band signup/accounts (**Q-002**), relay restart deployment (**Q-014**), modifications to the roadmap, or degrading anonymous access for unclaimed subdomains.
- **Continuity Semantics (§3):** Bearer tokens serve strictly as continuity proofs rather than human identities.

## 2. Coherence and Internal Consistency

- **Conceptual Disambiguation ([`SPEC.md` §2](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L20-L41)):**  
  The distinction between `registered` (active live tunnel in `core.Registry`), `reserved` (exclusive name/port entitlement in `core.Reservations`), and `durable` (disk-backed persistence in Slice 2) is maintained. Active connection conflicts continue to yield `ErrNameTaken` from `core.Registry`, while ownership entitlement conflicts yield `ErrNameReserved` from `core.Reservations`.
- **Cryptographic Model & Token Validation ([`SPEC.md` §3.1, §5.1](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L65-L80)):**  
  Storing `sha256(token)` in hex with `crypto/subtle.ConstantTimeCompare` is soundly justified by enforcing `core.MinTokenLen = 16`. Tokens shorter than 16 characters fail fast with `ErrTokenTooShort` across both `Claim` and `Check` (§5.1, §6), preventing insecure low-entropy secrets from being hashed or silently degraded to anonymous.
- **Port Holding Mechanics ([`SPEC.md` §5.2](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L190-L212)):**  
  `core.PortPool` introduces a `held` state. Keying ownership by subdomain rather than ephemeral `agentID` ensures that re-dialing agents retain port entitlements. Generic `Allocate` skips held ports, while `AllocateSpecific` succeeds only for the designated holder.
- **Single Authorization Funnel ([`lessons/L-009`](file:///home/m/dev/pumasi/lessons/L-009-two-paths-one-claim.md), [`SPEC.md` §5.3](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L213-L242)):**  
  Both agent ingress (`ServeAgent`) and SSH ingress (`ServeSSH`) pass through `Relay.authorize`, ensuring consistent reservation enforcement across both transport paths without duplicated or diverging logic.
- **Handshake Atomicity & Rollback ([`SPEC.md` §5.1](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L181-L189)):**  
  `Claim` reports `created bool`, enabling `Relay.authorize` to trigger `Discard` if subsequent handshake steps (such as registry binding or announcement) fail, ensuring uncompleted handshakes do not strand reservations.

## 4. Edge Cases & Boundary Handling

The specification and decision table ([`SPEC.md` §5.1, §6](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L161-L173)) comprehensively handle non-trivial edge conditions:
- An owner reconnecting without specifying `--tcp-port` (`tcpPort == 0`) retains its existing port reservation rather than clearing it.
- An owner attempting to claim a second distinct port for an existing name is refused (`ErrPortReserved`), bounding port allocation to 1:1 per reservation.
- Two distinct subdomains attempting to claim the same public port are refused with `ErrPortReserved`.
- Documented known failure modes (§8) explicitly record unauthenticated plaintext wire exposure, race-on-first-claim dynamics, and SSH client token limitations as documented design boundaries.
