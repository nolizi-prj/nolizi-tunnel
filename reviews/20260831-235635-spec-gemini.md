## 1. Coherence and Internal Consistency

### Core Architectural Strength
The conceptual division between `registered` ([`core.Registry`](file:///home/m/dev/pumasi-tunnel/core/route.go)), `reserved` ([`core.Reservations`](file:///home/m/dev/pumasi-tunnel/core/reservation.go)), and `durable` (Slice 2 Store) is well articulated (§2). Slicing honesty across §4 and §7 is maintained, explicitly leaving the durable restart column (§4) to Slice 2 and freezing `D-1` as an unfulfilled test for the next iteration.

### Critical Contradiction: §5.1 Rollback vs. §11 Concurrency Guard
There is a direct contradiction between the rollback invariant defined in [SPEC.md §5.1](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L181-L189) and the concurrency guard introduced in [SPEC.md §11](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L440-L442):

- **[SPEC.md §5.1](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L181-L189)** explicitly states:
  > *"A claim records a handshake that completed... if anything after that fails — **the registry refuses the name as live**, the bind fails, the announce fails — the relay calls `Discard` for a claim `created` by that handshake. **So a name is never consumed by a connection that never opened.**"*
- **[SPEC.md §11](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L440-L442)** introduces the guard:
  > *"**The fix** is one guard: `discardClaim` returns early **if the registry still has the name**."*

**The Collision:**
Consider the common scenario where an anonymous agent is active on subdomain `N` (unclaimed in reservations, live in the registry per §6 row 2). A new caller arrives presenting `subdomain: N` with a valid token `T`:
1. In `authorize`, `Claim` succeeds and reports `created = true` because `N` was not previously in `Reservations`.
2. Next, `Registry.Register` runs and fails with `ErrNameTaken` because the anonymous agent is currently registered under `N`.
3. Handshake failure triggers rollback via `discardClaim(newClaim)`.
4. However, `discardClaim` inspects `r.registry.Has(N)`. Because the anonymous agent is live, `Has(N)` is `true`, causing `discardClaim` to return early without discarding the claim.
5. The connection is aborted and closed, having **never opened a tunnel**.
6. Yet `N` remains permanently claimed by token `T` in `Reservations`. When the anonymous agent eventually disconnects, neither they nor any subsequent anonymous agent can re-use `N`.

This breaks the invariant in §5.1 that *"a name is never consumed by a connection that never opened"* on the very first failure trigger named in that clause (*"the registry refuses the name as live"*).

### Unspecified Transition to the Held State (§5.2, §5.3)
[SPEC.md §5.2](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/SPEC.md#L198-L204) defines `Hold`, `Unhold`, and `Holder` on `PortPool`, but neither §5.2 nor §5.3 specifies the relay call sites that invoke `Hold` or `Unhold`. While the implementation in `relay.go` places `Hold` in `authorize` and `Unhold` in `discardClaim`, the normative specification prose omits when and where the relay transitions a port to and from the `held` state.

## 2. Acceptance Test Suite and L-006 Analysis

- **Coverage of Discard Rollback:** Acceptance case `C-7` ([acceptance/CASES.md](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/acceptance/CASES.md#L71)) only covers post-claim failure caused by port bind conflict (`listenTCP`), where the registry is empty. It does not test post-claim failure caused by `Registry.Register` returning `ErrNameTaken` when a live tunnel exists.
- **Unit Guard Inadequacy:** The in-package test [`TestDiscardClaimWillNotUnderrunALiveTunnel`](file:///home/m/dev/pumasi-tunnel/relay/discardclaim_test.go#L27) tests a live tunnel owned by the claimant, not a live tunnel owned by a stranger or anonymous squatter.
- **[L-006](file:///home/m/dev/pumasi/lessons/L-006-tests-that-cannot-fail.md) Exposure:** Because `C-7` only exercises the `registry.Has == false` branch, the entire test suite passes green while the clause in §5.1 (*"the registry refuses the name as live ... leaves nothing behind"*) is completely inoperative and contradicted by §11.

## 3. Spec vs. Intent Statement Alignment

[INTENT.md §"What should be true instead"](file:///home/m/dev/pumasi-tunnel/spec/0004-names-with-owners/INTENT.md#L74-L77) states:
> *"The relay hands a name to a stranger only when nobody has claimed it."*

Under the contradiction between §5.1 and §11, a claimant who was refused connection because an anonymous user was active nonetheless captures the reservation during a failed handshake. Once the anonymous user disconnects, the anonymous user is locked out by a handshake that never completed, violating the intent of trust-on-first-completed-use.
