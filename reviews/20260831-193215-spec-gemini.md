## 1. Coherence & Internal Consistency

- **Root Cause & Multiplexer Ordering Analysis ([`SPEC.md` §2](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/SPEC.md#L27-L57)):**  
  The specification correctly refines the analysis in legacy documentation. In `spec/0002`, the assumption was made that `mux.Server(conn)` could not be instantiated prior to the auth handshake response because of reader interference. `SPEC.md` §2 demonstrates that the reader poses no contention (the agent sends nothing between the auth request and its first mux stream). Instead, the true hazard is write ordering: `mux.Session.Open` writes stream control frames (`FrameOpen`) under `Session.writeMu`, whereas the auth response is written directly to the raw connection without locking `mux.Session`. A naive reorder (installing the session in `r.sessions` before writing the auth response) creates a race where incoming visitor traffic can place a `FrameOpen` onto the wire ahead of the auth response, corrupting the agent's initial handshake frame decode (`core.DecodeAuthResponse`).
- **Dual-Purpose Synchronization Mechanism ([`SPEC.md` §3.1](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/SPEC.md#L58-L87)):**  
  The specification addresses both requirements (session visibility prior to URL release and exclusion of stream frames before the handshake completes) using the existing `r.mu` RWMutex in [`relay/relay.go`](file:///home/m/dev/pumasi-tunnel/relay/relay.go#L222-L236):
  1. *Ordering:* `ServeHTTP` takes `r.mu.RLock()`, blocking visitor dispatch while `ServeAgent` holds `r.mu.Lock()` during session insertion and auth-response transmission.
  2. *Exclusion:* Visitors cannot acquire a session handle or trigger `OpenStream` until `r.mu.Unlock()` executes, ensuring `okFrame` is always the first byte sequence on the agent's connection.
- **Lock Contention & Deadlines ([`SPEC.md` §3.2](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/SPEC.md#L88-L112)):**  
  Holding a lock across a socket write is justified and bounded:
  - The encoded `AuthResponse` frame is small (< 4 KiB) and fits comfortably in kernel TCP send buffers.
  - The handshake deadline (`conn.SetDeadline(now + HandshakeTimeout)`) remains active across the announce write and is only cleared afterwards, ensuring stalled clients cannot hold `r.mu` indefinitely.

## 3. Acceptance Cases & Test Invariants ([`lessons/L-006`](file:///home/m/dev/pumasi/lessons/L-006-tests-that-cannot-fail.md))

All three acceptance cases defined in [`acceptance/CASES.md`](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/acceptance/CASES.md) and implemented in [`relay/sessionorder_test.go`](file:///home/m/dev/pumasi-tunnel/relay/sessionorder_test.go) are deterministic, construct explicit synchronization barriers rather than relying on timing races, and contain no conditional assertion structures:

- **C-1 ([`TestVisitorIsNotAnsweredBeforeTheSessionExists`](file:///home/m/dev/pumasi-tunnel/relay/sessionorder_test.go#L180-L224)):**  
  Uses `gatedConn` to pause the relay inside the auth response write. Dispatches a visitor request while held. Asserts that the visitor is not answered (blocked on `r.mu.RLock()`) rather than receiving a premature `404`, and verifies that the request completes with HTTP `200` once the announce is released.
- **C-2 ([`TestTheAnnounceReachesTheAgentBeforeAnyStream`](file:///home/m/dev/pumasi-tunnel/relay/sessionorder_test.go#L233-L266)):**  
  Verifies stream frame exclusion. With a visitor dispatched during the held announce, asserts that the agent receives and decodes a valid `AuthResponse` as its first frame, proving no `FrameOpen` bypassed the handshake frame.
- **C-3 ([`TestAFailedAnnounceLeavesNothingBehind`](file:///home/m/dev/pumasi-tunnel/relay/sessionorder_test.go#L280-L370)):**  
  Forces write failure on the announce via `failingConn`. Asserts that `delete(r.sessions, ...)` and `abandon()` clean up all routing state atomically: the hostname returns `404`, and a subsequent agent can immediately register and serve the same subdomain.

## 4. Edge Cases & Boundary Handling

1. **Announce Write Failure ([`SPEC.md` §3.3](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/SPEC.md#L113-L126)):**  
   If `r.writeFrame(conn, okFrame)` fails, `delete(r.sessions, resp.AgentID)` is executed inside the *same* `r.mu.Lock()` block before releasing the lock, preventing a race window where concurrent visitors could obtain a dead session handle.
2. **Teardown Race Disambiguation ([`SPEC.md` §3.4](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/SPEC.md#L127-L140)):**  
   The `session == nil` branch in [`ServeHTTP`](file:///home/m/dev/pumasi-tunnel/relay/relay.go#L363-L373) is documented as strictly unreachable during startup, remaining solely for teardown when an agent disconnects before registry unregistration completes.
3. **SSH and TCP Isolation ([`SPEC.md` §4–§5](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/SPEC.md#L141-L174)):**  
   SSH ingress registers sessions upfront without an announce write race, and TCP port listener bindings remain properly positioned before the announce as established in `spec/0002`.
