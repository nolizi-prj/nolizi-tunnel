## 1. Specification and Intent Conformance

The commit addresses the race condition where incoming visitor HTTP requests arriving immediately upon URL registration received spurious `404` errors before the multiplexer session was installed in `r.sessions`:

1. **Atomic Session Registration & Auth Frame Write ([`SPEC.md` §3.1](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/SPEC.md#L58-L87)):**  
   In [`relay/relay.go`](file:///home/m/dev/pumasi-tunnel/relay/relay.go#L222-L236), [`ServeAgent`](file:///home/m/dev/pumasi-tunnel/relay/relay.go#L139-L265) instantiates `muxSession{s: mux.Server(conn)}`, acquires `r.mu.Lock()`, registers `r.sessions[resp.AgentID] = session`, and writes `okFrame` across `conn` while holding `r.mu`.
   - **Ordering:** Incoming requests in [`ServeHTTP`](file:///home/m/dev/pumasi-tunnel/relay/relay.go#L339-L422) calling `r.mu.RLock()` block until `r.mu.Unlock()`, preventing `404` responses during the announcement phase.
   - **Wire Exclusion:** Because [`ServeHTTP`](file:///home/m/dev/pumasi-tunnel/relay/relay.go#L360-L363) cannot acquire the session pointer until `r.mu.Unlock()`, no visitor can invoke `session.OpenStream(false)` to place a `FrameOpen` frame onto the shared connection ahead of the `okFrame` handshake response.

2. **Atomic Failure Path Cleanup ([`SPEC.md` §3.3](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/SPEC.md#L113-L126)):**  
   If `r.writeFrame(conn, okFrame)` returns an error, `delete(r.sessions, resp.AgentID)` executes within the *same* critical section before `r.mu.Unlock()`. Any visitor goroutine queued on `r.mu` will read `session == nil` upon gaining read access and receive HTTP 404 rather than being forwarded to a broken multiplexer session. Post-unlock, `session.Close()` and `abandon()` ensure full resource and registry cleanup.

3. **Handshake Deadline Invariants ([`SPEC.md` §3.2](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/SPEC.md#L88-L112)):**  
   The handshake deadline `conn.SetDeadline(time.Now().Add(r.cfg.HandshakeTimeout))` remains active across the `r.writeFrame` call. `conn.SetDeadline(time.Time{})` is executed only after `r.mu.Unlock()`, ensuring bounded lock duration even if the remote peer stalls on socket read.

4. **Teardown Documentation ([`SPEC.md` §3.4](file:///home/m/dev/pumasi-tunnel/spec/0003-session-before-announce/SPEC.md#L127-L140)):**  
   The `session == nil` comment in [`ServeHTTP`](file:///home/m/dev/pumasi-tunnel/relay/relay.go#L363-L373) has been accurately updated to reflect that startup races are closed by the lock synchronization and this branch only handles disconnect teardown.
