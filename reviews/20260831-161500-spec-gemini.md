## 1. Coherence & Internal Consistency

- **Single Source of Truth ([L-007](file:///home/m/dev/governance/lessons/L-007-restating-a-rule-forks-it.md)):** [`SPEC.md`](file:///home/m/dev/pumasi-tunnel/spec/0001-public-scheme/SPEC.md) §1 specifies `core.Registry.publicScheme` via `Registry.PublicURL` as the single point of decision for URL scheme construction across all three user surfaces:
  1. CLI output via `AuthResponse.URL`
  2. Apex console status feed via `/_pumasi/status`
  3. SSH ingress greeting via `sshGreet`
- **Data & Configuration Flow:** The flow defined in §2–§3 is unidirectional and unambiguous: `flag` (`-public-scheme`) $\rightarrow$ `relay.Config.PublicScheme` $\rightarrow$ `relay.New` (validation via `core.ParsePublicScheme`) $\rightarrow$ `core.NewRegistry` $\rightarrow$ `Registry.publicScheme`.
- **Validation & Safe Defaults:**
  - `core.ParsePublicScheme` normalizes inputs (`http`, `https`, case insensitivity, surrounding whitespace, and trailing `://`) and resolves empty input to `http`.
  - Unrecognized schemes cause `relay.New` to halt immediately with `core.ErrUnknownScheme`.
  - `core.NewRegistry` defaults safely to `http` if given unvalidated input, preventing unroutable URLs from leaking into registry consumers.
- **URL Construction Invariants:** §4 defines $PublicURL(N) = S + \text{"://"} + lower(N) + \text{"."} + D$, preserving label lowercasing, base-domain normalization, and scheme-less raw TCP addresses.
